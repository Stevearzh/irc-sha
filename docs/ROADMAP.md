# irc-sha 落地路线（ROADMAP）

> 目标：实现可以在 IRC 频道中进行的标准版三国杀（文字驱动）。
> 本文档记录 2017 版代码的解析结论、核心难点、架构决策与分阶段路线。
> 后续每个阶段完成后更新对应勾选状态。

## 一、2017 版现状解析（存档结论）

### 架构分层

```
package/card/*.csv    卡牌数据：标准包 104 张 + EX 包 4 张
isha/
├── dict/             常量字典：花色/牌型/牌名、事件名、身份、玩家状态机定义
├── core/             基础设施层：card / event / player(状态机) / table / dispatcher
│                     / parser / calculator / identity / factory / system
├── model/            规则内容层：杀闪桃 + recipe 注册表、游戏开始等事件
└── game/listener.py  event_system 单例（未接入）
```

### 设计思想

1. 一切皆事件：`dict/event.py` 预定义 30+ 事件名（为武将技能钩子预留）。
2. 玩家状态机：基于 `transitions` 库，正常/响应杀/伤害结算/濒死/死亡。
3. 调度器 → 卡牌解析器：出牌走"能否使用 → 放桌面 → 触发 → 等待响应 → 伤害结算 → 弃牌"管线。
4. 数据驱动卡牌：csv 描述牌堆构成，recipe 把牌名映射到类。

### 停滞位置与问题

- `example.ipynb` 演示的最远边界：开局 → 发牌 → 出杀 → 目标进入"被杀"状态；**响应链从此断开**（`core/parser.py` 中 `# wait for target response / yield ...` 注释处）。
- 代码无法运行：`model/card/basic.py:63` 存在全角逗号 `，`（U+FF0C）语法错误。
- `sha.__effect` 引用不存在的 `self.__passive`；`eval` 动态拼接调用脆弱。
- 回合制、濒死求桃、死亡奖惩、胜负判定均未实现；锦囊/装备只有 csv 数据没有实现。
- IRC 前端零代码；`system.py` 事件系统未接入。

## 二、难点定性

三国杀的真正难点不是单张牌的效果，而是其结算模型是
**一棵可嵌套、可被打断、需要多玩家异步输入的结算栈**：

- 出杀 → 等目标出闪 → 伤害结算 → 濒死 → 逆时针逐人求桃（每次求桃又是一个响应窗口）→ 死亡 → 奖惩。
- 无懈可击可在任意锦囊生效前插入，且可嵌套无懈可击。
- 武将技能要在几十个时机点插入结算。
- IRC 是消息驱动的异步环境，玩家输入随时到来、可能超时——与"同步函数调用栈"式结算天然冲突。

2017 版方案（transitions 状态机 + eval + 同步 `__call__` 链）在结构上无法表达
"全局结算栈 + 等待多人响应"的状态，这是当年卡住 root cause。

## 三、架构决策

**核心思路：引擎做成"纯状态机 + 结算栈"，与 IO 彻底分离；用"响应窗口"统一所有等待玩家输入的场景。**

```
┌──────────────── IRC bot 前端（阶段5）────────────────┐
│  频道消息 ⇐ 渲染 Effect      私聊输入 ⇒ 解析为 Action │
├──────────────── 本地 CLI 前端（阶段2）────────────────┤
╞═════════ 引擎边界：apply(action) → [Effect] ═════════╡
│  GameEngine                                          │
│   ├─ 玩家/牌堆/座次/回合阶段（纯数据状态）            │
│   ├─ 结算栈：生成器调用树（牌使用/伤害/濒死/锦囊嵌套）│
│   ├─ pending: Ask（响应窗口：谁被问 / 合法动作校验 / 超时默认）│
│   └─ 事件钩子点：dict/event.py 时机 → 技能挂载处      │
├──────────────── 内容层（数据驱动）────────────────────┤
│  卡牌规则注册表 + csv 牌堆数据 + 未来武将技能         │
└────────────────────────────────────────────────────────┘
```

1. **引擎纯化**：`engine.apply(action) -> [Effect]`。引擎不等待、不碰 IO、不用墙钟；
   需要输入时挂起并暴露 `pending: Ask`；随机性通过注入的 `random.Random(seed)`。
   IRC、CLI、单元测试（脚本化 Action 序列 + 固定种子）共用同一引擎。
2. **结算栈用生成器调用树实现**：`yield Ask` 挂起等待输入，`yield from` 嵌套子结算。
   无懈可击套无懈可击 = 调用树加深一层，天然支持。退役 transitions + eval。
3. **Ask 统一响应模型**：每个 Ask 带合法动作校验函数与超时默认动作
   （不出闪/不出桃/自动弃牌）。多人求桃 = 按座次逐个产生 Ask。超时由前端调用
   `engine.timeout()` 注入默认动作，引擎不关心时间。
4. **Effect = 公开信息**：可直接广播到频道，不含他人手牌等私密数据；
   私密信息（手牌、可选动作）只通过 Ask 发给对应玩家（IRC 走私聊）。
5. **保留的资产**：`dict/` 常量字典、csv 牌堆数据与 factory 思路、身份分配、
   环形距离计算、`assign_card` 文本选牌协议（`h10杀` 风格，适合 IRC）。

### 文本选牌协议（沿用）

```
<花色字母><点数><牌名>，花色 S/H/C/D = ♠♥♣♦，点数含 10 时用两位
牌名可省略（花色+点数在单副牌中唯一）
例如：DK杀、d6闪、S9杀、h10杀、dq桃、H8
```

## 四、分阶段路线

- [x] **阶段 0 — 重启地基**：Python 3.11+；venv + pyproject + pytest；
      迁移 dict/identity/距离计算/选牌协议；旧 core（eval/transitions）整体退役。
- [x] **阶段 1 — 最小可玩引擎**：回合轮转（摸牌→出牌→弃牌，判定阶段预留）+
      杀/闪/桃 + 伤害/濒死求桃/死亡奖惩/胜负判定；脚本化测试跑完整局。
- [x] **阶段 2 — 本地前端**：CLI 热座 + Web 热座（`python -m isha.game.web`，
      标准库 http.server 零依赖），验证 Ask/Action 交互与超时模型。
- [x] **阶段 3 — 锦囊全家桶**：无懈可击（可嵌套抵消的响应窗口）、南蛮/万箭
      （逐目标响应+逐目标抵消）、决斗、顺手/过河、无中/五谷/桃园、
      乐不思蜀/闪电（判定阶段 + 判定区 LIFO）。
      顺手/过河由使用者选牌（手牌暗牌盲选、判定区明牌直选，可拆乐不思蜀）。
      借刀杀人依赖武器，推迟到阶段4。牌堆当时扩至 85 张（阶段4 已补全至 104 张）。
- [x] **阶段 4 — 装备与距离修正**：装备四槽（武器/防具/+1/-1 马）、
      方向距离（-1 马缩短进攻、+1 马增加防御）、借刀杀人、
      顺手/过河支持装备区。武器特效：连弩无限杀、青釭剑破防具、青龙追杀、
      贯石斧强命、麒麟弓射马、丈八双牌当杀、方天画戟多目标杀
      （最后一张手牌的杀至多三目标、按座次逐一结算）；八卦阵判定闪；
      EX 包寒冰剑（防止伤害改弃两张牌）与仁王盾（黑杀无效）亦已落地。
      雌雄双股剑特效待做（需性别系统）。
      牌堆完整 104 张（启用 EX 包 108 张）。
- [ ] **阶段 5 — IRC 前端**：bot 挂频道；开局/报状态走频道消息，手牌与操作走私聊；
      断线超时托管（默认动作）。
- [ ] **阶段 6 — 武将技能**：事件总线上挂技能钩子（dict/event.py 时机点启用）。

## 五、已明确不做的权衡

- 不写"修复续命"路线：旧 core 仅约 500 行且核心（响应链/回合）未实现，
  eval/transitions 结构无法表达结算栈，重写比重修便宜。旧代码由 git 历史保存。
- 引擎暂不做状态快照/序列化持久化；断线恢复靠 Action 日志重放（阶段 5 再议）。
